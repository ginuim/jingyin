# 镜隐 iOS 端首发方案

## 结论

建议先做 iOS，再做 Android。

镜隐的核心难点是端侧 AI 推理、视频逐帧处理、硬件解码/编码和长视频稳定性。iOS 设备与系统组合更集中，适合先把产品链路和性能边界做稳定，再把成熟方案迁移到 Android 的多厂商环境。

## 首发目标

第一版不是完整替代网页端，而是验证以下闭环：

1. 用户从相册或文件中选择视频。
2. 在设备本地识别人、宠物和车辆。
3. 对主体或背景进行遮盖处理。
4. 支持原声、静音和基础变音。
5. 在本机完成导出并保存到相册或分享面板。

原视频、模型推理数据和导出结果均不上传服务器。

## 推荐技术栈

### 客户端

- 语言：Swift
- UI：SwiftUI
- 视频访问与播放：AVFoundation、AVPlayer
- 视频解码/编码：VideoToolbox、AVAssetReader、AVAssetWriter
- 图像帧处理：Core Video、Metal
- 模型推理：Core ML；必要时通过 Metal Performance Shaders 做自定义算子
- 音频处理：AVAudioEngine；导出阶段使用 AVAssetReader/Writer 保留、静音或替换音轨
- 文件与分享：Photos framework、Share Sheet、FileProvider（后续）

Apple 的 Core ML 支持在设备端运行模型，并建立在 Accelerate、BNNS 和 Metal Performance Shaders 等底层能力之上；VideoToolbox 提供硬件视频压缩与解压能力。

参考：

- [Core ML](https://developer.apple.com/documentation/coreml/)
- [VideoToolbox](https://developer.apple.com/documentation/videotoolbox)

## 模型方案

### 第一版建议

- 先使用轻量级目标检测/分割模型，优先保证稳定帧率和功耗。
- 模型输入统一缩放到 320 或 384 边长，避免直接对 4K 原图推理。
- 对同一目标使用简单追踪，减少每帧重复推理。
- 模型推理与视频编码解耦：推理生成遮罩，编码线程消费遮罩和原始帧。
- 设备不支持合适的 Neural Engine/GPU 能力时，降级到较低分辨率或较低处理精度。

### 处理档位

| 档位 | 目标 | 建议行为 |
| --- | --- | --- |
| 低 | 快速预览 | 较低分辨率、较低推理频率、矩形/椭圆遮罩 |
| 中 | 默认处理 | 目标检测 + 追踪 + 中等分辨率分割 |
| 高 | 精细导出 | 更高分辨率分割、逐帧等待遮罩、只对较新设备开放 |

## 视频处理架构

```text
相册/文件
   ↓
AVAssetReader 读取视频帧
   ↓
帧缩放与 Metal 预处理
   ↓
Core ML 推理 + 目标追踪
   ↓
生成遮罩并应用模糊/像素化效果
   ↓
VideoToolbox / AVAssetWriter 编码
   ↓
保存到相册或系统分享面板
```

必须避免在主线程执行以下操作：

- 模型加载和首次预热
- 视频帧批量读取
- Core ML 推理
- 大尺寸遮罩合成
- 视频编码和音频重采样

主线程只负责界面状态、进度、取消操作和错误提示。

## 版本与设备策略

首发建议支持最近几代主流 iPhone，具体最低系统版本在模型和编码器验证后确定。不要在第一版承诺覆盖所有旧设备。

建议建立设备能力表：

- 系统版本
- 芯片型号
- 是否支持目标 Core ML 计算单元
- 可用内存
- 硬件编码器能力
- 720p/1080p/4K 的单帧推理耗时
- 15 秒、1 分钟、5 分钟视频的导出耗时与峰值内存

高精度档位应根据能力表动态开放；不满足条件时，明确切换到中档，而不是让用户等待一个不可完成的任务。

## MVP 页面

1. 首页/导入页：选择视频、显示本地处理承诺。
2. 编辑页：视频预览、遮盖范围、主体选择、处理档位、声音处理。
3. 处理页：阶段状态、百分比、预计剩余时间、取消按钮。
4. 结果页：预览、保存到相册、系统分享、重新处理。

处理页至少区分：

- 正在读取视频
- 正在加载模型
- 正在预热模型
- 正在分析画面
- 正在编码导出
- 已完成
- 可恢复失败

## 开发阶段

### 阶段 0：技术验证

- 在 2～3 台代表性 iPhone 上跑通 Core ML 模型。
- 验证 1080p 视频解码、遮罩合成和 H.264/HEVC 导出。
- 测量首帧时间、单帧推理耗时、峰值内存和设备温度。

### 阶段 1：可用 MVP

- 完成导入、预览、主体遮盖、静音/原声和导出。
- 先支持 720p/1080p，限制视频时长和文件大小。
- 加入取消、失败重试和降级策略。

### 阶段 2：高精度能力

- 接入实例分割模型。
- 引入目标追踪，减少重复推理。
- 支持更细的边缘处理和高档导出。
- 建立设备能力分级和耗时提示。

### 阶段 3：发布准备

- TestFlight 内测。
- 重点收集导出失败、发热、内存峰值、后台切换和相册权限问题。
- 完成隐私说明、数据处理说明和 App Store 审核材料。

## 首版验收指标

- 1080p、1 分钟视频在目标设备上可完成导出。
- 处理过程中主界面持续响应，取消操作可在短时间内生效。
- 模型加载失败、内存不足、编码器不可用时都有明确提示。
- 不发生原视频上传；网络断开不影响已下载模型和本地处理。
- 处理结果可正常保存、播放和分享。

## Android 衔接

iOS 版本稳定后，再将以下模块抽象成跨端协议，而不是直接复制实现：

- 处理档位与能力检测
- 模型输入/输出格式
- 遮罩数据结构
- 进度状态机
- 错误码与降级策略

Android 第二阶段可采用 Kotlin、Jetpack Compose、Media3 Transformer/MediaCodec 与 LiteRT 或 ONNX Runtime。Media3 Transformer 基于 MediaCodec 和 OpenGL，适合硬件加速视频转换，但需要额外覆盖不同厂商和系统版本。

参考：[Media3 Transformer](https://developer.android.com/media/media3/transformer)

## 当前决策

首发平台：iOS。

首发重点：本地短视频处理稳定完成，并纳入照片批量打码；再扩大设备覆盖和功能范围。人脸贴纸与车辆识别后置。

定价：当前售价 ¥28 / $4.99；美国目标 $9.99（稳定后永久改价）；中国大陆先观察。详见 [app-store-market-and-pricing.md](./app-store-market-and-pricing.md)。

Android 与鸿蒙：在 iOS MVP 的模型、遮罩、导出和错误处理协议稳定后进入下一阶段。
